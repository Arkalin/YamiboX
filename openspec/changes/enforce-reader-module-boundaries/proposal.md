# Proposal

## Why

现有阅读器虽已按目录区分领域、流程、数据和界面，却仍与论坛、具体 Store 和应用模型共用两个聚合模块，目录约定不能强制限制依赖。以完整阅读器为第一个受保护业务，在有限数量的业务与基础设施模块之间建立可失败的依赖准入规则，并让当前论坛通过中立契约提供内容，为以后替换数据源保留真实入口。

## What Changes

- 保留一个仓库和一个 Swift package，以 `YamiboXCore`、`YamiboXUI`、`YamiboXReader`、`YamiboXLibrary`、`YamiboXForum`、`YamiboXForumSource`、`YamiboXUserData` 七个源码 targets 加现有 App 为实施布局；数量来自职责划分，不以增加 target 为目标。
- 阅读器、收藏与论坛的业务流程、ViewModel 和 UI 分别归属 Reader、Library、Forum。现有 UI target 收窄为薄公共 UI；Core 收窄为真正跨模块的领域值、必要契约和少量基础能力。协议、适配器及 Domain／Application／Data 目录不各自占用 target。
- 先形成粗粒度的最终所有权，再首先验收 Reader 的完整边界。Reader 只依赖中立 Core 和公共 UI，不能直接或经共享模块获得论坛、持久化、其他业务或 App 实现。模块访问控制与依赖声明、import、重新导出及 API 检查共同提供约束。
- 论坛通信、解析、来源模型和阅读适配归属 ForumSource；数据库、文件、Store、迁移与原子提交归属 UserData，用户数据 WebDAV 同步先作为其内部子系统。Source 的窄缓存接口由 App 内适配代码连接 UserData，不另建 Adapter target，也不把所有网络访问集中到 Source。
- 将作品、章节、内容片段、资源、位置和数据源分页定义为来源中立的契约。阅读器不再理解 `tid`、板块、论坛页码、作者过滤和 HTML；这些解释与转换由论坛阅读适配层负责。
- 将设置、进度、历史、注解、封面、目录持久化和离线队列改为按阅读器实际需要提供的能力接口，不把每个 Store 原样复制成协议。
- 阅读器 ViewModel、加载／布局／导航／注解协调器和正文视图留在 Reader 内。论坛原帖、评论编辑器等界面归属 Forum，通过 App 的类型化宿主接口接入；App 负责最终装配和跨业务协调，不接收所有未归类的业务实现。
- 保留唯一正式数据源及现有阅读行为。通过临时固定内容适配器验证小说、漫画与资源加载可替换，不增加正式第二数据源、来源选择 UI 或插件系统。
- 保持既有数据库、缓存、恢复路由与 WebDAV 格式兼容；数据身份转换留在适配层，原有跨业务事务、提交后通知及账号代次保护不变。
- **BREAKING**：内部 Swift 模块归属、导入路径和阅读器装配 API 将调整，仓库内调用方同步迁移；不承诺保留旧的宽依赖初始化器或重新导出全部旧 API。此处不是用户数据格式或产品交互的破坏性变更。

本期包含净化共享模块所必需的论坛数据、用户数据及非阅读 UI 归属调整，不能以保留旧 Core/UI 聚合实现换取少改文件。Library、Forum 先完成实际业务归属，其尚未收窄的数据依赖按 design 的有限过渡清单登记，后续变更再完成严格边界；它们不是本期第二、第三条完整业务验收线。不拆数据库，不新增独立 Sync target，不借机重构全部非阅读业务。

## Capabilities

### New Capabilities

- `reader-module-boundaries`：以阅读器为首个完整保护对象，约束业务 UI、共享模块、宿主集成和公开 API 的归属，对直接及传递依赖实施可失败的构建准入，明确非阅读业务的过渡边界。
- `reader-source-contracts`：通过来源中立的阅读与资源契约接入当前论坛和替换验证装配，划分来源缓存语义与实际存储责任，同时保持身份、持久化和运行时兼容性。

这两项新增的是开发期依赖准入和数据源接入契约，不是新增阅读器产品功能；现有阅读交互保持不变。当前项目尚无主规格，无需修改既有 capability。

### Modified Capabilities

无。

## Impact

- 构建与检查：`Package.swift`、App 的 Xcode package products 接线、`scripts/check-architecture.sh`、现有 CI 架构检查入口、`docs/architecture.md`，以及模块边界相关的项目指引。
- 当前 Core：阅读流程与契约、论坛网络／解析与阅读适配、Library 等业务、全部持久化与同步、设置／账号状态、图片数据加载和资源所有权，按新职责分配而非整目录照搬。
- 当前 UI 与 App：阅读器、收藏／历史／详情／下载管理、论坛／登录等业务界面；公共视觉与平台桥接；App 装配、设置聚合、导航及跨功能生命周期。归属调整不意味着上述业务都完成了严格接口改造。
- 数据与行为：迁移代码归属和运行时接口，不借机改写历史迁移、存储键或 WebDAV payload；本地测试环境验证现有行为及替换入口。
- 验证授权：不新增单元测试、测试文件或测试 target。若实现期间确需新增，另行请求明确批准；本变更规划使用架构检查、临时编译探针及本地 App 交互验证。

本轮仅更新既有五份规划文件，不修改应用代码，不启动实施。
