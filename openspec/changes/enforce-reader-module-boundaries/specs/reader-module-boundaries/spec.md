# Spec Delta

## Purpose

以完整阅读器为首个受保护业务，建立覆盖工作流、ViewModel、界面及共享依赖闭包的准入规则。业务 UI 归属自己的业务模块，共享模块保持中立，其他业务经受限入口集成阅读，不得借公共 UI、应用宿主或迁移例外访问阅读器内部状态与具体数据实现。

## ADDED Requirements

### Requirement: 阅读侧依赖受到强制准入限制

项目的构建准入流程 SHALL 将完整阅读模块限制为只依赖中立共享契约、薄公共 UI 及明确允许的基础依赖。阅读模块及其共享依赖闭包 MUST 不包含来源数据实现、具体持久化实现、其他业务模块或应用宿主。该规则 MUST 同时覆盖模块依赖声明、源码导入和重新导出，不得仅依靠目录命名或人工约定。

#### Scenario: 增加非法模块依赖
- **WHEN** 开发者给阅读模块声明一个指向来源、持久化、其他业务或应用宿主的依赖
- **THEN** 架构检查返回非零状态并说明违规依赖，构建准入失败

#### Scenario: 通过源码导入绕过声明
- **WHEN** 阅读侧源码导入或重新导出禁止模块，包括带访问级别或放在条件编译分支内的导入
- **THEN** 构建准入拒绝该改动，不因当前编译环境恰好能够解析该模块而放行

#### Scenario: 通过共享模块间接引入实现
- **WHEN** 阅读模块的直接依赖不变，但共享契约或公共 UI 新增指向来源、存储或业务实现的依赖
- **THEN** 依赖闭包检查拒绝该改动，不能以阅读源码没有直接 import 为由通过验收

#### Scenario: 只装配允许的阅读依赖
- **WHEN** 使用包含工作流、ViewModel 和 UI 的完整阅读模块，以及中立 Core、薄公共 UI 和允许的基础依赖构建独立消费方
- **THEN** 不需要提供来源、具体存储、其他业务或原 App 模块即可完成编译

### Requirement: 业务界面与共享能力具有受限所有权

阅读、收藏管理和论坛的业务流程、ViewModel 与业务 UI SHALL 归属相应业务模块；公共 UI SHALL 仅提供实际复用的展示能力，不得持有具体 Store、来源客户端、应用模型或其他业务的内部状态。共享 Core SHALL 仅接纳真实跨模块的领域值、必要契约及少量基础能力，不得将来源 DTO、数据库记录或业务实现集中其中以规避依赖限制。

#### Scenario: 公共组件携带业务服务
- **WHEN** 一个拟纳入公共 UI 的组件依赖具体论坛服务、存储、应用模型或功能 ViewModel
- **THEN** 该组件不能通过公共模块边界验收，必须留在业务模块或先分离值和动作驱动的通用展示部分

#### Scenario: 以共享模型名义引入来源页面
- **WHEN** 为避免转换而把来源页面模型或数据库实现搬进共享 Core，并让阅读器直接使用
- **THEN** 该改动不能通过来源中立性及共享 API 验收，不因其已经位于 Core 而获得准入

#### Scenario: 迁移含资源的公共或业务组件
- **WHEN** 组件及其独占资源调整模块归属
- **THEN** 新所有者可以通过正确资源包加载资源，现有本地化、论坛表情和图片展示保持可用，不依靠重复资源副本绕过边界

### Requirement: 非阅读过渡依赖不得稀释阅读边界

项目 SHALL 明确区分目标依赖图、当前允许的非阅读过渡依赖和已完成验收的边界。过渡依赖 MUST 有具体消费者、用途及移除条件，并受统一准入检查；完整阅读边界验收 MUST 不接受经任何过渡入口取得具体实现。不得把非阅读业务完成模块归属等同于其全部接口已经隔离。

#### Scenario: 非阅读业务暂时直接使用数据能力
- **WHEN** 收藏或论坛业务保留在允许清单内的直接数据依赖
- **THEN** 仅该登记用途获得准入，阅读模块和共享模块仍不能依赖这条路径，交付记录明确该业务尚未完成严格边界

#### Scenario: 新增未登记的迁移例外
- **WHEN** 开发者新增超出当前允许清单的依赖或用迁移兼容入口绕过阅读边界
- **THEN** 架构准入失败，不能通过把依赖命名为兼容层或扩大共享可见性静默放行

### Requirement: 模块内部实现不得成为跨模块使用入口

阅读模块 SHALL 通过受限的根入口、值模型和消费能力与外部协作。阅读器内部 ViewModel、加载、布局、导航和生命周期实现 MUST 不对模块外调用方开放；跨边界签名和默认实现 MUST 不暴露具体存储、来源页面模型、应用模型或通用服务定位器。

#### Scenario: 外部访问内部协调器
- **WHEN** 外部模块试图构造或访问阅读器内部 ViewModel 或内部协调器
- **THEN** 编译失败，调用方必须通过受限阅读入口集成

#### Scenario: 协议或工厂带回具体实现
- **WHEN** 新的跨边界接口通过参数、返回值、关联类型或默认参数引入来源页面模型或具体存储实现
- **THEN** 该接口不能通过阅读模块编译与边界验收，不能通过扩大可见性或转导出规避

### Requirement: 阅读器自身行为不能移出边界以规避检查

小说与漫画的阅读 ViewModel、内容加载准入、布局、位置恢复、注解和阅读生命周期状态 SHALL 由受保护的阅读模块拥有。应用宿主 SHALL 仅负责应用导航、跨模式展示协调及外部功能集成，不得代为执行阅读器内部流程后把阅读模块降为空展示壳。

#### Scenario: 独立阅读宿主
- **WHEN** 独立宿主仅提供契约要求的服务和类型化动作打开小说或漫画
- **THEN** 阅读器能够自行准备内容、导航、恢复位置、更新展示和结束会话，不要求宿主持有内部 ViewModel

#### Scenario: 原帖与阅读模式互相切换
- **WHEN** 当前应用从嵌入式帖子切换到全屏阅读，再切回原帖
- **THEN** 应用宿主完成模式交接，阅读模块管理自己的加载与取消，旧会话的退出回调不能覆盖新模式的恢复路由

### Requirement: 外部功能通过类型化宿主边界接入

阅读器 UI SHALL 通过有限的请求、结果和来源能力接入关闭、模式切换、原文、评论及其他外部页面。该边界 MUST 不要求具体应用对象、论坛会话、外部功能 ViewModel 或不透明的任意服务箱；现有论坛来源已经提供的功能 SHALL 保持可用。

#### Scenario: 从阅读器打开论坛评论编辑界面
- **WHEN** 当前来源声明支持评论，用户请求查看或编辑章节评论
- **THEN** 宿主使用自己的论坛依赖展示相应界面并返回必要结果，阅读器 UI 不需要引用论坛编辑器或论坛会话类型

#### Scenario: 外部操作失败
- **WHEN** 原文打开、评论提交或模式切换失败
- **THEN** 失败仍按现有交互反馈，阅读器不把失败当成成功关闭或丢弃当前有效内容

### Requirement: 状态和平台服务具有明确生命周期

模块拆分后的阅读器 SHALL 保持逐会话状态身份、持续变更观察和既有过期请求保护；共享外设和图片服务 SHALL 经显式注入复用。初始快照 MUST 不替代持续观察，界面重建 MUST 不重复创建全局监听或隐式启动正式来源请求。

#### Scenario: 阅读期间设置或注解变化
- **WHEN** 设置、目录或注解在其他受支持入口发生变更
- **THEN** 当前阅读会话收到真实变更并更新相应展示，不因只注入启动快照而停留在旧状态

#### Scenario: 关闭后旧加载完成
- **WHEN** 阅读器关闭或切换账号后，旧内容、布局或注解请求才返回
- **THEN** 旧结果不更新已结束或新的会话，必要的已发起持久化写入仍按原有规则完成或报告失败

#### Scenario: 界面重复构造
- **WHEN** 宿主更新导致阅读根视图再次初始化
- **THEN** 活跃会话身份与共享外设处理器栈保持正确，不新增重复监听或丢失已有阅读状态

### Requirement: 新路径与违规样例纳入统一检查

项目 SHALL 对全部源码模块的路径与依赖声明执行统一登记和各自适用的准入规则，并拒绝未登记的新增源码模块。阅读边界验收 MUST 包含合法独立构建和违规直接／传递依赖、违规导入、内部实现访问、来源类型泄漏的负向证据；不得把检查脚本无报错当作全部行为已验证，也不得把阅读模块内部目录说成独立编译层。

#### Scenario: 新增源码 target 或移动文件
- **WHEN** 新增 target 或把阅读源码移动到新的受保护模块路径
- **THEN** 该 target 必须显式登记规则，移动后的源码仍受检查，未覆盖路径不能静默通过

#### Scenario: 验证检查有效性
- **WHEN** 在隔离的验证环境分别引入禁止的直接／传递依赖、禁止导入、内部实现访问和来源模型泄漏
- **THEN** 对应检查或编译失败并给出可定位的结果，合法基线仍通过，用户工作树不被违规样例覆盖

### Requirement: 拆分不改变现有阅读体验

正式来源的小说与漫画阅读 SHALL 保持既有阅读模式、目录和位置恢复、书签／喜欢／笔记、离线缓存、图片操作、外设及自适应展示行为。预览模式 SHALL 继续不写入正常阅读进度、恢复路由或收藏最近阅读状态。

#### Scenario: 从现有入口恢复阅读
- **WHEN** 用户从详情、收藏、历史或应用恢复入口打开已有小说或漫画
- **THEN** 按既有规则恢复内容范围和位置，阅读、注解、缓存及关闭行为不因模块迁移改变

#### Scenario: 预览后退出
- **WHEN** 用户打开预览阅读、翻页并退出
- **THEN** 正常阅读的进度、恢复路由和收藏最近阅读状态不被预览位置覆盖

#### Scenario: 设备布局与输入变化
- **WHEN** 阅读器在手机或 iPad 上发生受支持的布局变化或接收已配置的外设输入
- **THEN** 内容、翻页、缩放、选区和安全区域保持既有有效行为，不出现由模块拆分引入的状态重置或输入重复执行
