# Tasks

任务对应本变更两份规格与 `design.md`。第 2–8 组可先在原 Core/UI 编译布局内完成责任拆分，第 9 组是协调的物理归属切换；不能把逻辑拆分阶段的构建记录当成最终依赖闭包证据。若旧变更已先实施，仅复用经核对的结果，不重复搬迁或自动勾选其任务。

以下验证使用现有构建、架构脚本、临时集成装配和 Local App 交互，不授权新增单元测试、单元测试文件、测试 target 或 UI 测试 host。所有运行验证只使用签名有效的 `YamiboX-Local` 与本地论坛；启动规则参照 `docs/tests/launch-arguments.md`。各组随实现维护相关文档与证据，最后一组只做跨组集成验收。

## 3. 来源环境、通用传输与非论坛网络

- [ ] 3.2 提取 Core 中立传输契约和 App Foundation 执行桥接，让 `YamiboClient` 只掌握论坛请求、重定向准入和 WAF/重放策略；用本地请求验证响应体上限、重定向限制、字节进度与取消均保留，来源不创建隐藏 URLSession 或磁盘存储。
- [ ] 3.3 拆分 `NetworkLoggedTransport` 的逐尝试事件与 `NetworkLogStore` 的持久执行，经注入端口替代共享记录器；验证重试/重定向记录仍可关联，报告不含 Cookie、授权头或私密正文，日志错误不会被误报为请求成功。
- [ ] 3.4 将 WebDAV 传输留在 UserData、应用版本更新编排落在 App，均注入中立传输并保留原有账号授权前置条件；验证使用本地/内存网络材料时无需实例化论坛来源即可完成请求和失败处理，未授权同步仍被拒绝。
- [ ] 3.5 更新 `docs/architecture/networking-and-routing.md` 与 `docs/architecture/webdav-sync.md` 的传输、环境和日志职责；核对实际调用链及本组验证记录，启动参数语法仅在原专用文档按必要变更维护。

## 4. 会话安全与账号生命周期

- [ ] 4.1 将 `SessionState` 中论坛 Cookie/域/登录判断移入 Source，保留 UserData 私有历史编码及通用凭据值，来源仅接收快照/有效性/条件更新端口；验证本地已有 vault 与旧会话样本可读，来源构造不持有具体 SessionStore/AccountStore。
- [ ] 4.2 将 WAF/凭据更新与预期会话代次校验合并到受保护提交边界，保留请求发出前及关键 await 后检查；通过延迟本地请求并切换账号验证旧响应、旧 WAF 结果不能更新新会话或被发布成当前结果。
- [ ] 4.3 迁移远端认证仓储和候选登录接线，保留账号操作 lease、候选 ephemeral 网络/网页/存储及 UID 校验；用本地候选登录失败、取消和身份不符流程验证活跃账号未提前改变，租约正确释放。
- [ ] 4.4 将跨模块账号转换/重置编排放入 App 生命周期区域，保留草稿、同步屏障、下载/网页停止等待、缓存清理、提交及实际会话收尾顺序；验证有在途活动时的切换/退出及至少一个提交失败路径，不无条件回滚或误报激活成功。
- [ ] 4.5 更新 `docs/architecture/account-lifecycle.md`，列出远端协议、vault、平台清理和 App 编排的当前入口；逐项核对 lease/generation/epoch 的职责及本组竞态证据，明确设备共享业务数据未改为账号分库。

## 5. 缓存与资源管线

- [ ] 5.2 保留首页/板块缓存代次、在途写入登记和清理等待边界；通过本地延迟写回与账号清理交错验证旧写入不重新填充已失效范围，并核对线程缓存及共享数据仍采用原策略。
- [ ] 5.3 将普通图片 `DataCache`、`YamiboMaintainedImageDataCache` 与物理文件维护归 UserData，通过窄同步字节端口接 Source 的 Nuke 适配；验证冷/热缓存、清空与维护交错、失败后的调度行为，无主线程同步等待异步 Store。
- [ ] 5.4 将封面、离线及远端资源统一接入中立资源引用，保留 Source 的签名、请求合并、冷却和 WAF 策略，UI 仅解码展示；验证本地图像在线/离线读取、取消、相同 URL 不同授权上下文及代次失效，普通磁盘 key 和共享离线文件不变。
- [ ] 5.5 更新网络/路由与下载/存储文档中的缓存、图片责任和失效范围；核对源码/本组记录准确区分内存在途请求身份与现有磁盘共享策略，并说明 UserData 使用现有 Nuke 缓存实现而非依赖 Source。

## 6. 下载载荷、持久队列与身份一致性

- [ ] 6.1 从 `DownloadPayloadFiles`/`DownloadStore` 提取 Source 的来源页 codec、内容投影与下载材料准备，UserData 接收中立元数据及兼容字节；验证基线小说/漫画离线内容仍可打开，活跃下载接口不暴露论坛 DTO 或 Reader 实现。

- [ ] 6.3 将活跃来源内容身份校验改为注入的纯同步能力，保持 `MangaIdentityMigrationV1` 私有 schema-1 DTO 冻结；验证损坏/错身份载荷仍被拒绝、旧迁移样本仍可读取，事务内校验无网络、异步等待或重新进入 Store。
- [ ] 6.4 接通 UserData 持久执行器到中立来源/资源能力，保留小说逐页刷新和既有队列恢复、进度、取消/停止等待；用本地延迟响应验证删除/替换任务后旧结果不能恢复条目或覆盖新文件，不出现第二套工作者。
- [ ] 6.5 将目录编辑后的下载、历史、喜欢/书签等身份提交保留为 UserData 跨业务原子命令，维持提交时记录版本检查与提交后通知；验证本地目录重映射成功和失败时各表/文件引用一致，不产生半提交通知。
- [ ] 6.6 更新 `docs/architecture/downloads-and-storage.md` 与 `docs/architecture/persistence-and-identity.md` 的材料准备、纯校验、提交权及队列停机边界；核对本组旧数据/竞态证据并准确标注模拟器无法确认的系统后台表现。
