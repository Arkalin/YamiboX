# Design

## Context

动机和产品范围见 `proposal.md`，行为以两份 delta spec 为准。本设计只基于当前 Core／UI 两个源码 target，不读取其他模块拆分规划作为实施前提，也不调整其文件。

已核对的当前实现：

| 位置 | 现状及影响 |
| --- | --- |
| `YamiboX/YamiboXApp.swift` | 普通 `WindowGroup` 与统一 scene delegate，没有专用外屏角色、窗口或登记生命周期 |
| `Sources/YamiboXUI/AppEntry/YamiboWindowCoordinator.swift` | 共享服务、逐窗口模型、焦点及聚合前后台状态；外屏不能作为普通第二窗口加入同一套归属推导 |
| `Features/Reader/Shared/ReaderSession.swift`、`ReaderSessionView.swift` | 已有模式切换、恢复路由和 contentID；小说／漫画活跃 model 仍在根 View 的 `@State`，不能仅复制 session 根视图 |
| `Features/Reader/Novel/Root/NovelReaderView.swift` | 视口、注解、面板和 model 由 View 持有，`onDisappear` 会保存并关闭 model，迁移显示时必须与真正结束区分 |
| `Features/Reader/Manga/Root/MangaReaderView.swift` | 根 View 持有 model，出现／消失时注册和移除外设 handler，缩放状态还在视口中 |
| `Features/Reader/Manga/Viewports/Paged/MangaPagedLayoutPolicy.swift` | 双页要求设备是 iPad 且视口足够宽；外屏必须显式传入显示环境而非伪装整个设备身份 |
| `Features/Reader/Shared/Chrome/ReaderChromeControls.swift` | 按钮已有动作闭包，可供本地点击和外屏激活复用 |
| `Features/Reader/Shared/Comments/ReaderChapterCommentsViews.swift` | 评论有滚动、菜单、编辑 sheet、图片／帖子／用户覆盖页，需要面板路由而非仅转发翻页 |
| `Sources/YamiboXCore/Settings/Domain/GamepadSettings.swift` | 已有四类离散动作，不是连续指针协议，不应把高频光标输入写入持久化外设绑定模型 |

表中 `Features/...` 均相对 `Sources/YamiboXUI`。当前无测试 target；`docs/tests/launch-arguments.md` 明确 Local App 仅支持模拟器。

## Goals / Non-Goals

**Goals:**

- 分离阅读会话与展示位置，迁移时保持状态身份、单一进度来源和可恢复生命周期。
- 为应用拥有的阅读控件接入明确操作，复用原业务动作而非实现另一套阅读规则。
- 让失败、系统交互和前后台中断都有可回退的设备端界面。

**Non-Goals:**

- 不新增 package target、通用远程桌面框架或跨进程协议；所有输入均在同一 App 内。
- 不将 App 或 UI 平台状态塞入 Core，不变更阅读进度、设置、下载及同步的持久化格式。
- 不承诺任意系统控件都能被软件光标点击，不使用私有触摸注入或依赖 SwiftUI 私有视图结构。

## Decisions

### 1. 使用专用外屏场景，设备保留输入所有权

在 App 入口按平台版本接入 `windowExternalDisplayNonInteractive`，由 `YamiboXUI/AppEntry` 下的外屏协调器管理窗口、登记对象和连接身份。设备窗口保留实际触摸、键盘和文字输入；外屏只渲染内容与应用内光标。

Apple 当前文档规定 iOS 27 起通过 scene accessory 注册才收到此场景；iOS 18 至此前版本走外屏 scene 配置／delegate。使用 availability 分支封装差异，避免两条路径重复创建窗口。登记绑定拥有者阅读宿主，仅在其具备外显资格时启用，持有登记对象直到解除；不为每个弹窗重新登记。App 启动服务未就绪时先等待，不创建第二套运行时。依据：[Presenting content on a connected display](https://developer.apple.com/documentation/uikit/presenting-content-on-a-connected-display)。

替代方案：普通 `WindowGroup` 可能变成可调整大小的外屏窗口，不保证本需求的专用全屏；屏幕镜像则不能让设备只显示触控板提示。

有线是本期兼容性和验收范围，不额外承诺“可靠识别并屏蔽所有无线显示连接”。系统外屏 API 同时可能收到 AirPlay 场景，不凭音频路由、分辨率或 `isCaptured` 猜测 DP 链路。额外外屏不参与本期会话分配。

### 2. 在现有模块内提升会话状态，迁移视口而非复制阅读器

在 UI 阅读会话层持有小说／漫画的活跃呈现状态，根 View 改为接收稳定引用。阅读数据、加载、导航和进度语义仍留在 Core；平台窗口与坐标只留在 UI。可复用现有 `ReaderSession` 的身份和模式生命周期，但不把窗口实例注入 Core ViewModel。

需要提升的状态至少包含 model、注解协调、面板路由、当前语义位置和尚未结束的文字交互；纯显示的几何缓存、手势识别器、滚动视图实例随视口重建。漫画缩放／平移在迁移时保存可恢复的内容焦点，按新几何收敛，不保存跨屏像素 offset 作为阅读位置。

区分 `detachViewport`、`suspend` 和 `closeSession`：迁移只解除旧视口报告、几何观察和输入 handler，不能沿用小说当前 `onDisappear` 的保存后关闭逻辑。真正退出仍走既有保存与关闭流程，必要写入不能因视图任务取消而丢失。

每次展示位置变化生成新的呈现代次，与 session/contentID 一起验证位置回调、异步恢复和输入。一次只准许一个有效视口报告进度；先同步旧视口当前位置、冻结其报告，再恢复新视口，待新内容准备完成后解除遮罩并切换设备为触控板。新视口恢复期间不提交首屏占位位置。既有持久化写入保持顺序，不能只挡 UI 回调却让旧异步保存最后覆盖存储。

替代方案：两份 ViewModel 双向同步会放大加载、观察、保存竞态；简单保存后重开会丢失面板／草稿状态并重复启动阅读流程，均不采用。

### 3. 以状态机统一连接、暂停和设备交互

外屏协调器保留拥有者窗口、session、连接代次和呈现代次。状态转移全部在主线程协调，流程中的内容加载仍复用现有异步能力。

```text
local --> preparing --> external
  ^          |             |
  +----------+             +--> deviceInteraction --> external
  |                        |
  +----- disconnect -------+--> suspended ----------> external
```

| 状态／事件 | 行为 |
| --- | --- |
| `local` | 不启用专用外屏阅读；可用外屏与合格前台会话同时出现才准备接管 |
| `preparing` | 设备仍有阅读界面，冻结旧视口位置提交；外屏内容恢复完成后才进入 `external` |
| `external` | 外屏是唯一有效阅读视口；设备显示提示并处理触控板输入 |
| `deviceInteraction` | 保留会话和面板返回目标，外屏显示中性遮罩，设备承载编辑或系统面板，暂停遥控 |
| `suspended` | 拥有者设备场景不可交互时遮蔽／撤下 App 外屏内容，取消手势并保存位置，等待同一拥有者恢复 |
| 任意状态断线 | 撤销外屏输入与报告；未编辑时恢复设备阅读，编辑中保留本机交互，结束后回到本机阅读 |
| 会话结束／拥有者窗口销毁 | 解除登记、取消输入、移除光标和唤醒需求，按既有关闭语义结束；不自动换另一本书 |
| 接管失败 | 退回可用本机阅读，显示一次错误；同一连接和会话失败代次不无限重试，重连或重新进入阅读器可重新尝试 |

前后台判断使用拥有者设备场景而非“所有场景中只要一个 active”的聚合状态，防止外屏仍 active 时错误维持阅读。开始本机交互先设置路由，再展示系统面板，避免其引发 inactive 时丢失交互。隐私遮罩在失去可交互状态时尽早设置，但不保证 OS 截图或硬件链路每一帧的显示内容。

接管前按已有实际触摸／按键事件记录最近使用的合格阅读器，而非 `onAppear` 次序；无操作历史时用当前前台合格阅读宿主作为确定性后备。接管后固定所有者，焦点变化可以暂停输入但不能换会话。关闭拥有者后，只有新的明确阅读激活才重新选择，不把剩余窗口立即补上。

防自动锁屏采用 UI 层拥有者令牌／需求聚合，只在有效触控板期间持有，释放时不能无条件覆盖其他场景的唤醒需求。替代方案：分别在各 View 的出现／消失回调设置布尔值容易互相覆盖，故将其纳入协调生命周期。

### 4. 用显式目标注册连接软件光标与现有业务动作

在阅读 UI 层增加局限于该功能的输入路由与目标注册能力。目标包含稳定 ID、所属交互层、有效区域、可用状态、激活动作及可选的拖动／滚动／缩放操作。SwiftUI 控件通过布局锚点报告外屏坐标，UIKit 视口桥接公开的内容 offset／zoom 操作；不把所有控件都转换成 UIKit，也不遍历私有层级寻找按钮。

注册按 scene／会话／呈现代次隔离，渲染结束时更新有效目标集合，移除隐藏或销毁目标。命中考虑可见裁剪、层级和禁用状态；模态面板开启时遮断底层，即使点击面板外也不翻正文。单指点击调用与设备触摸相同的动作闭包，保持失败提示、权限检查和业务副作用的原语义。

现有 `ReaderChromeIconButton` 等集中入口先接入；目录行、设置开关／滑块／选择器和评论操作逐项覆盖。对 `Menu`、系统 sheet 导航或其他无法通过明确动作遥控的应用控件，外屏采用应用拥有的等价弹层／选择列表，设备端原呈现保持不变。外屏面板与光标处于同一受控呈现树，确保光标不会落在 sheet 后面；必要的独立承载根必须显式加入同一交互层路由。

UIKit 的公开触摸文档描述系统事件接收；它不是跨屏合成任意触摸的保证。本设计依据公开动作与绑定完成遥控，而不是尝试调用识别器接收方法伪造系统事件。参考：[UITouch](https://developer.apple.com/documentation/uikit/uitouch)、[UIControl](https://developer.apple.com/documentation/uikit/uicontrol)。

替代方案：辅助功能遍历或模拟点击可用于有限验证，但不是可靠的产品操作协议；重写全部阅读 UI 又会复制业务逻辑，均不采用。

### 5. 连续输入独立于既有外设绑定，手势一次只认一种操作

触控板由 UIKit 多点触控桥接识别单指移动／轻点、双指平移和捏合。移动增量使用 points 和明确的设备／外屏坐标变换，按外屏有效区域限位，不把设备触点绝对位置映射为光标。单指触点增加到两指时取消单指点击候选；双指操作结束后剩余一指需重新起手，避免补出点击。

双指起手记录光标命中目标与内容状态，在短暂识别阶段区分平移和捏合；识别后固定类别。优先级如下：

1. 当前最上层面板内的可拖动控件捕获平移，并更新同一个值绑定。
2. 面板滚动区域处理自身滚动，正文不参与。
3. 漫画内容有效捏合以光标附近的内容点为缩放焦点，不能同时触发翻页。
4. 非捏合的双指移动在放大漫画中平移，到边界不翻页。
5. 普通正文按模式连续滚动或在有效方向／阈值后执行一次现有翻页动作，遵守阅读方向；无效或被取消手势不提交翻页。

控件拖动被捕获后，手指间距变化不再切换成漫画缩放。小说上识别出的捏合不修改字号，也不降级为翻页。手势取消时释放目标，不向新窗口补发动作。分页命令复用原有漫画内容边缘／阅读方向处理；“放大后不得越界翻页”优先于既有离散翻页行为，故不把该手势直接转成键盘命令。

光标位置和空闲计时独立于大范围阅读状态观察，防止每次移动重排正文。默认深色触控板底色、浅灰居中文字；初始中心、空闲约 3 秒隐藏的要求见规格。阈值和相对移动增益为内部参数，先使用一致默认值，经模拟器交互调整，不新增设置页。现有键盘／手柄继续走原动作语义，但共用会话与交互层准入，避免重复注册和输入穿透。

### 6. 显式展示环境和设备交互路由

向阅读布局传入当前视口尺寸、安全区域、scale 和本机／外屏呈现种类。外屏尺寸从实际承载窗口获取，不读取 `UIScreen.main`，也不全局修改 `UIDevice` 的设备判断。小说的排版环境和漫画双页策略分别接收显示能力；本机仍维持原手机／iPad 行为。双页的既有有效适配规则继续生效，不把临时布局写回用户设置。

阅读搜索、评论回复与笔记编辑等由设备交互路由保存编辑身份和草稿，主设备提供输入框／编辑控件及系统键盘。完成回传业务结果，失败继续编辑；外屏通过中性遮罩避免显示输入内容。权限提示、照片选择和分享也从设备宿主发起。交互 token 绑定原会话及有效账号，断线保留编辑；会话关闭后迟到结果不得恢复旧外屏或自动提交。

普通目录、设置和评论浏览仍在外屏。跳转原帖、用户空间等阅读范围外的目的地交回既有设备导航并停止专用外屏阅读，用户返回合格阅读器时重新按自动接管规则判断。应用无法阻止的系统呈现不被描述为完全可控的外屏图层。

替代方案：在外屏放一个真实文本输入框会把键盘焦点与设备屏幕分离；把全部面板搬回设备又违背触控板交互，因此只路由已批准的输入与系统例外。

## Risks / Trade-offs

- [软件光标能移动但部分菜单无法操作] -> 先验证“目录选择、设置滑块、评论返回、设备编辑”的完整链路，再扩展目标接线；外屏采用等价受控弹层，不能把显示成功当作可用。
- [视图消失触发关闭／旧保存覆盖进度] -> 提升会话所有权、区分 detach 与 close、约束保存顺序及代次；同时检查内容加载中、换章节和快速重连。
- [外屏 active 掩盖设备已离开] -> 以拥有者设备场景为准；设备交互与普通后台中断分开建模，遮罩先于挂起。
- [指针、目标区域和动画错位] -> 使用外屏坐标空间，更新可见几何，捕获期间固定目标；动画中无有效命中区域时不执行旧目标。
- [DP 链路／分辨率／Stage Manager 行为差异] -> 兼容性承诺仅基于实际验证设备；模拟器证明代码路径，不证明物理输出或延迟。
- [真机验证尚未授权且 Local 配置仅支持模拟器] -> 本次实现不扩展配置、不换生产 App；记录未验证项，后续明确授权硬件、隔离构建与测试站点后再执行物理链路验收。这是验证缺口，不是实施其余任务的阻塞门槛。
- [合成光标不等于系统辅助功能指针] -> 保留设备提示的可访问文本及现有本机无障碍行为，不宣称外屏软件光标已自动获得完整 VoiceOver 导航能力。

## Migration Plan

1. 在当前模块内建立稳定会话所有权和视口切换，先证明不接屏时阅读、关闭、恢复和预览无回归。
2. 接入版本化外屏场景和最小显示链路，同时处理准备失败、断线、暂停和隐私遮罩。
3. 建立输入目标路由并先打通目录、设置滑块、评论与设备输入的完整链路，然后接入全部本期阅读面板、两类视口与双指仲裁。
4. 执行本地验证矩阵，记录缺口；不新增单元测试、测试文件或测试 target，也不复活已移除的 UI 自动化宿主。

无需数据库或同步数据迁移。若需回滚本功能，撤销外屏登记与设备接管入口，保留原本机阅读路径；已完成的会话所有权调整仅在确认无其他改动依赖时随功能撤销，不回退用户数据或其他任务文件。

验证入口沿用 `AGENTS.md` 与 `docs/tests/launch-arguments.md`，运行签名 `YamiboX-Local` 和本地 `http://127.0.0.1:8088`，不复制或新增启动参数。实施时在 `docs/tests/external-display-reader.md` 记录小说／漫画、分页／滚动、iPhone／iPad 模拟器、菜单与输入、失败／断线／后台／多窗口场景及结果。若模拟器工具无法产生双指输入，应明确列为交互验证缺口，不用单元测试替代实测，也不以“编译通过”勾掉该行为。

## Open Questions

- 相对移动增益、双指平移／捏合判定阈值需要在有效外屏尺寸上调校；不改变已确认的手势优先级或增加设置项。
- 后续实机验收使用的设备型号、系统版本、DP 线材／转接器和隔离构建方式待用户另行授权时确定；当前不据此承诺兼容性或启动真机测试。
