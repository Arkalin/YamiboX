# 清理代码注释

1. 确定本轮范围。用 `bash scripts/check-comments.sh inventory [Git 路径规格 ...]` 盘点 Swift 注释；省略路径则扫描全仓 Swift。输出每个注释的文本、位置及 `wholeLines`（只含注释的物理行，每行只计一次）。其他语言按各自语法检查。保留编译指令、必需的许可声明和工具生成的元数据；字符串里的注释符号不是源码注释。
2. 按相邻注释组阅读源码、调用方和已有设计文档，逐组记录分类与去向：
   - **Tautology**：代码已经直接说明了同一件事。删除。
   - **Stale**：可证实与现行实现、已支持的平台或调用方式不符。删除。
   - **Excuse**：有具体证据表明注释在为有待修复的变通辩护。删除，并查重跟踪根因；有明确发布授权才提交 GitHub Issue，否则在结果中交付草稿。写明源码位置、影响或风险、验收条件，不把静态推断写成已复现。一个根因只开一个 Issue，敏感发现不公开。
   - **Decision Record**：解释代码本身看不出的重要取舍或约束。将背景、选择、理由及源码链接移入 `docs/adr/`；已有 ADR 就补充，不复制。核对记录之后再删除原注释。
3. 做减量，不做行为重构。证据不足、尚未迁移的说明或未获授权发布的问题保留在基线，明确标注待处理。保留注释周围的 token 边界，并用语法感知的方式比对删改前后的 Swift；对其他语言运行相应语法检查。
4. 运行 `bash scripts/check-comments.sh prune` 和 `bash scripts/check-comments.sh check`。基线只许缩小；不能靠刷新放行新增或改写的注释。遵循 [AGENTS.md](../../../AGENTS.md) 完成必要验证，并汇报删除的纯注释行数、剩余行数、ADR、Issue 和未验证项。
