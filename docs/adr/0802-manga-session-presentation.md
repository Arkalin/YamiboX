# 漫画阅读会话区分来源、内容与视口

一个漫画会话可从任一章节进入并跨多个论坛帖阅读，也可在设备窗口和外接显示器间换宿主。入口身份、当前内容和原生视口的状态变化频率不同，不能互相充当代理信号。

## 来源和注解

- [漫画 ViewModel](../../Sources/YamiboXUI/Features/Reader/Manga/Root/MangaReaderViewModel.swift)按启动来源的板块搜索目录；旧路由缺少板块时才回退到历史默认板块 `30`，不覆盖依赖提供的冷却和时钟。书签与喜欢的锚点记录来源板块，重新打开时采用板块当前的阅读方式，而不是锁定收藏时的模式。
- 「打开原帖」优先定位当前章节的主人帖：跨章节以后，入口帖不再代表正在读的章节。尚无当前页时回到入口帖，保证加载或出错时也能打开原帖。[漫画 View](../../Sources/YamiboXUI/Features/Reader/Manga/Root/MangaReaderView.swift)把入口、启动章节和目录章节的帖号传给讨论浮层，从那里查看同一作品不单独记一次浏览历史。
- 智能模式可能先拿到目录，再拿到注解作品身份；在这段时间，目录应仍可单独打开。书签标记按章节内的离散页匹配；笔记归属于喜欢，但读者可以直接添加笔记，应用负责先创建或复用该页的喜欢，不要求手动分两步。

## 内容和呈现

- 阅读界面从实际挂载的窗口取安全区，尚未挂载时用容器几何，外屏则用宿主提供的几何。iPad 状态栏的安全区可能先于信息栏淡出消失，信息栏因此保留最近一次可见的顶部 inset，避免淡出中跳动。
- 翻页操作由当前视口先判断。键盘、手柄和 Apple Pencil 与边缘点按共用分页视口的判断，缩放或按高度适配时先揭示当前页未显示的部分。控制器翻页或滚动时收起工具栏，加载或出错时仍可用菜单键显示关闭按钮。双页的中缝属于同一个可缩放表面；单页只在命中图片时开始远程缩放。连续滚动模式在滚动边缘显式跳到相邻章节，沿用分页跨章的首末页规则。没有相邻章节时仍保留边界动作供执行路径反馈。
- 选中页和工具栏可见性不改变窗口的双页划分或缩略图索引。[漫画 View](../../Sources/YamiboXUI/Features/Reader/Manga/Root/MangaReaderView.swift)只在窗口或分页配置变化时重建对应数据，翻页只更新位置摘要。缓存初值可在 SwiftUI 构造视图时创建，实际读写留在 MainActor；ViewModel 的惰性协调器同样不是要被 SwiftUI 观察的状态。
- 内容每次提交都重新核对书签按钮和浏览历史。前者必须对应当前页，但逐页查询不应重算整个作品的书签与喜欢数量；后者可因目录合并或改名而变更，身份未变时由记录器去重。喜欢的变更统一从标记回写触发完整注解刷新；跳到喜欢或书签属于非线性内容导航，优先复用当前会话并记入前进/后退历史，无法跳转时才新开会话。
- 导航协调器管理历史候选和请求时序；真正的前进/后退恢复由 ViewModel 执行，因为恢复需要提交内容，以及由生命周期协调器停掉旧预取、按内容版本接纳结果。见[生命周期与提交边界](../architecture/readers.md#生命周期与提交边界)。
- [共享章节评论模块](../../Sources/YamiboXCore/Reader/Shared/Comments/ReaderChapterCommentsModule.swift)随调用者隔离，不把 Core 状态绑定到 MainActor。漫画 ViewModel 必须始终在 MainActor 驱动该实例：只有这一前提成立，才能在收到同步快照时用 `MainActor.assumeIsolated` 更新 UI。
