# 收藏页分批推导和发布展示状态

收藏页把文档写入和展示推导分开。写入在存储事务内对最新文档执行，不能以旧快照覆盖并发同步结果；缓存的选择位置统计只用于展示，不作为写入依据。读取失败保留最后一次有效的收藏和进度快照，避免把失败显示成「收藏为空」。见[持久化与身份](../architecture/persistence-and-identity.md)。

## 更新来源

- 初始加载恢复上次选择的分类、合集、排序和布局；常规重载不重新应用这些偏好。界面会先应用用户的操作、再异步保存，无关的后台更新不能用旧设置覆盖当前操作。设置与漫画目录各自订阅变更，按需刷新归组及封面；目录变更不手动重查进度，因为数据库进度流已经覆盖同一身份事务，迟到的手动读取反而可能覆盖新快照。
- 合并一次载入中连续写入的文档、导航和筛选变化，避免同一可见结果多次重建整个收藏。推导由每个收藏页自己的 worker 串行执行，不跨缓存实例复用；只发布最新代次，避免旧筛选的结果在新请求之后出现。
- 阅读器展示期间暂停收藏的进度订阅和推导。列表被阅读器遮挡时不重复查询进度，且返回的缩放动画仍能找到尚未被重新排序或移除的来源卡片。恢复订阅时重新读初始快照，以补齐阅读期间发生的删除和身份变更。
- 展示缓存命中也要建立观察依赖。目录映射不直接参与 Observation；通过修订值通知同数量替换。来源标签及标签计数读取文档，即使命中缓存也让 SwiftUI 订阅后续变更。后台同步删掉的标签要从活动筛选中移除，避免列表被看不见的筛选条件清空。

## 分类、合集和封面

载入、重载以及目录或版块设置变化时按 tid 批量解析目录，不在卡片渲染时逐项查库。展示推导只用启用智能漫画的成员；未读更新用全量目录映射，避免切换展示方式时隐藏已有更新。分类和合集共用 [Core 跨范围卡片投影](0103-favorite-library-projections.md)，再用直接分类位置及完整的「分类、合集」位置分桶。只放在合集里的条目不应同时算作分类中的直接卡片；合集的筛选匹配也必须在自己的成员范围内判断。条目计数和排序摘要不读取封面，不为它们叠加封面。

合集拼图从自身的成员而非已筛选的卡片中取最近四块，缺少图像时用文字。只有解析至同一个目录的智能漫画成员折叠；未解析、同猜测标题的章节仍分别显示，避免拼图与合集打开后的列表不一致。折叠块的封面和更新时间取全库的归档组，避免同一作品在不同合集显得属于不同的组。卡片用同一个封面键读取图片和文字封面标志，并用该键写入封面操作。

实现见[协调器](../../Sources/YamiboXUI/Features/Favorites/Engine/FavoriteLibraryOrganizer.swift)、[目录批量解析](../../Sources/YamiboXUI/Features/Favorites/Engine/FavoriteLibraryOrganizer%2BCovers.swift)与[展示推导](../../Sources/YamiboXUI/Features/Favorites/Engine/LocalFavoriteLibraryDerivation.swift)。
