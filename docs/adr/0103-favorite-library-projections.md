# 收藏列表把漫画作品卡与章节收藏分开

收藏保存帖子；漫画作品卡是从当前收藏和已知目录计算出来的视图，不写回收藏数据。用版块的智能漫画开关判定是否参与，不从目录是否已解析反推模式。已解析的卡用持久化目录 ID 聚合；未解析时，带 `unresolved-title:` 前缀的本地清洗标题只用于临时归档查找，不能把同名作品合并成一个目录。持久化身份的约束见[持久化与身份](../architecture/persistence-and-identity.md)。

## 作品卡与章节归档

- 原帖把收藏决定、写入和操作准入交给共享收藏命令，只在本地补充封面和即时反馈。只有找到同一目录的另一条已收藏章节，且双方各自版块均开启智能漫画模式，反馈才提示归属合并。目录可以跨版块；只检查刚收藏的一侧会让提示与收藏列表不一致。读图保留帖子封面入口；作品封面仅随当前版块显式模式与可用目录开放，目录残留或无法取得设置都不能代替模式开关。见[原帖的收藏反馈与封面](../../Sources/YamiboXUI/Features/Forum/ThreadReader/ForumThreadReaderViewModel.swift)。
- 在整份收藏中先按目录归组，再按分类和收藏夹筛选。作品卡出现在任一成员所在的位置，不因切换分类而变成另一组。用最早的收藏章节作代表和自动封面的候选起点；目录 ID 作为卡片身份，切换代表章节不应使选择丢失。如果目录不全，排序宁可沿用原成员顺序，也不丢弃成员。至少有两个成员才算实际合卡，单个已解析成员仍有完整的作品身份。
- 保留代表章节原有的帖子标题与数据，作品标题只在投影中取目录名或本地清洗结果。搜索已解析的卡时纳入目录名及各成员标题，不让用户只能搜到恰好被选作代表的章节。展示标题在构造时算一次，避免排序比较反复跑标题清洗的正则。
- 「查看归档收藏」替换分类和收藏夹范围，用与展示标签、批量选择展开相同的组键查找当前成员，将每条作为普通章节卡展示。否则原始章名和单章删除入口会被重复的作品卡吞掉。未解析归档页面用已出现的 tid 作临时锚点，保留已经显示的章节，也接纳仍匹配的新收藏；只有全部现存成员都解析到同一目录时才切换到该目录 ID。
- 卡片封面的读写使用同一个 `contentCoverKey`，避免切换文字封面时写入展示侧不读的行。已解析的作品卡（包括只有一个成员的卡）用目录 ID，归档内的单章卡及其他普通卡用各自的 tid；封面由独立存储提供，不写进收藏项。已解析的作品卡读目录进度，缺失时先找当前版块阅读模式对应的单帖进度，再找收藏原类型的进度；改变版块设置不应让此前的阅读记录消失。漫画的最近更新时间取成员已知的内容更新时间及目录中的章节发布日期（包括未单独收藏的章节），不把请求时间或目录刷新时间当作内容更新。

## 分类、筛选与排序

- 漫画收藏与其他帖子共用版块来源筛选；来源键按版块 ID 匹配，版块显示名变化不改变身份。
- 分类计数和收藏夹摘要使用同一份跨分类、未排序的卡片投影，再按位置分桶；逐个分类重复构建不能改变成员关系，只会重复分组及过滤。分组索引可以复用，但必须与收藏、目录及版块设置快照一致。标签和收藏夹元数据索引保留原输入中的排序并列项，包括尚未规范化的重复 ID。
- 组织排序不混排收藏夹和条目，因为收藏夹手动顺序与条目的论坛或创建顺序不能直接比较。其他模式给收藏夹用其名称、成员的最新日期或最小论坛收藏序号作比较值。日期排序默认最新在前，始终将无日期的条目留在末尾；标题和来源排序固定使用中文区域规则，使同一收藏库的顺序不受设备地区设置影响。

## 收藏状态与操作范围

[收藏状态快照](../../Sources/YamiboXCore/Library/Application/FavoriteMembershipSnapshot.swift)共用归档分组，一次批量查询支撑页面上的收藏状态、筛选和操作范围，不从初次收藏时的章节另推一套归属。没有目录时保留历史中已经确认的作品名，再次清洗可能改变身份；找不到组成员时仍识别旧版直接收藏的帖子，用户切换版块设置不应让这些记录消失。缓存只复用分组结果且限制存储实例数；每次读取的文档、目录和设置仍是权威，避免遗漏其他写入者或身份迁移。
