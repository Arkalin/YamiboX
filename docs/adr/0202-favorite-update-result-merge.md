# 收藏更新以同一个合并规则提交结果和计算角标

检查从快照出发，执行期间用户可以标记已读或忽略，目录也可能合并。[FavoriteUpdateStore](../../Sources/YamiboXCore/Library/Data/FavoriteUpdateStore.swift)在写事务中规范化目录身份，合并检测结果，而不使用旧快照覆盖数据库。以事件 ID 对照两侧，已有事件保留用户当前设置的已读/忽略时间；只出现在一边的事件也先纳入候选。每个目标仅最新检测可以保留为未忽略事件，这个“最新”需将已忽略事件也计入；否则旧快照会复活用户已经忽略的更新。目录合并时保留已知章节的并集，不受目录清理过往章节的影响，避免已经见过、后来重现的章节被误报为新。旧小说基线可能包含读者回复，版本缺失时不能当成当前的作者基线。

通知角标使用同一合并的未读、未忽略结果：只看数据库漏掉本次尚未提交的检测，只看运行快照漏掉用户在运行中的状态更新。[角标索引](../../Sources/YamiboXCore/Library/Data/FavoriteUpdateNotificationBadge.swift)区分运行本身的原始目标和提交时的规范目标；删除运行侧副本仍可露出同 ID 的数据库副本，失去最新事件时重新检查同目标的候选。加速路径只认同一运行、连续的序号和同一数据库修订；修订由事件表和共享身份重定向的触发器更新，也覆盖 Store 之外的写入。没有修订、出现重复事件标识或无法重用时按同一读快照走完整合并。

索引以唯一引用交给一个数据库读闭包，避免每次增量改变都触发整份字典的写时复制，也避免同时在多个任务中修改；较晚完成的旧读取仍可返回自己的正确值，但不可覆盖较新的基线。[运行事件累加器](../../Sources/YamiboXCore/Library/Application/FavoriteUpdateRunEventAccumulator.swift)在一次加锁中捕获版本、范围和计数，保留原顺序及旧槽位，允许之后按该版本重建快照，而不为每次通知复制整个事件数组。用语义值而非本地化文案记录运行进度，原始失败文本与进度分开。
