# 下载完整性用元数据快速判定，以源文件和持久引用为准

## 只在调用方需要时加载和验证正文

队列恢复以设备持久状态为准：并发调用共享同一次恢复，而且只记住成功的恢复，否则下一次显式请求需能重试。会写入队列或向管理界面报告状态的调用传播恢复错误，只有没有错误通道的可重建读取可以尽力继续。这保留了“没有下载”和“无法查询”的区别。

检查是否已有图片只探测资产记录和文件存在，不读取图片内容，也不顺手删除资产记录；真正读出图片时才清理无效记录。保存图片时只重查引用它的漫画章节。缺失资产缓存只是一条有界的反证，必须复核该位置仍引用该 URL 且资产仍缺失；旧行的 URL 如果会经 Foundation 规范化，则退回完整读取判断。即使没有已知缺项，仍须用有效源页、完整图片列表和文件存在判定完成。

漫画按作品批量读章节状态，避免逐页解码和逐图查库。已验证的源页按帖子、文件名、指纹和字节数缓存；正常的替换更新元数据后自然绕开旧缓存。按来源直接找图片仍保留源页有效性检查。小说管理投影一次仅保留一份已解码正文，不将整库正文驻留内存。只读作品投影只包括有完整下载的作品，不带队列状态；首次打开离线条目可用其来源重建路由，没有作者信息时仅接受唯一的作者匹配，不猜测。

## 自动刷新不是重下载

小说在线加载已下载源页时可刷新离线副本。先比对元数据、文件存在、图片引用和可重复的指纹，避免每次加载都编码正文、替换文件和写数据库。指纹使用排序的 JSON 键、原始日期显示文本，不纳入随访问、会话或采样时间变动的浏览计数、回复计数、表单 hash、管理操作和解析后的相对日期。完整源页仍原样保存。

真实写入在同一数据库写事务内复核条目并读取当前图片引用后替换文件；早先读事务和 actor 挂起前看到的状态可能已被删除或更新，不能用来重建已删除条目或覆盖并发写入的图片引用。

## 历史数据与文件升级

下载命名升级在旧漫画身份迁移运行完毕后执行，保持外键检查启用以确保表重命名时 SQLite 更新引用；索引名称另行迁移。新目录不存在时在同卷直接移动，不需要第二份磁盘容量。新旧目录并存时保留所有旧文件，直至目标全部核验一致，避免冲突时覆盖或崩溃后无法重试。身份重映射只改引用，不重命名 payload；冻结的迁移可能关闭 cascade，因此改父记录前读取子记录并显式处理子记录。只有冲突成员需要比较磁盘 payload。

完整清理会删除整个下载目录，重新创建目录时要重新设置系统备份排除。普通目录创建记录属性写入失败但不阻断触发它的下载。引用与目录详情见[下载与存储](../architecture/downloads-and-storage.md#8-下载命名升级的兼容边界)。
