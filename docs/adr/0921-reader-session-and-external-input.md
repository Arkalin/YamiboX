# Separate reader session ownership from viewport attachment and input

The [session](../../Sources/YamiboXUI/Features/Reader/Shared/ReaderSession.swift) carries cached thread state and resumable reading modes out of an embedded navigation column into a full-screen presentation. An explicit mode switch reclaims column ownership if dismissing a cover did not trigger appearance again. When handing a mounted reader back to the device, prepare it with device geometry before making it interactive. Saves carry a content identity so closing an old mode cannot replace the new route. Saving on exit to the original post is independent of the cancellable lookup; an accepted transition waits for that save rather than saving the old position a second time.

A [viewport lifetime](../../Sources/YamiboXUI/Features/Reader/Shared/ReaderViewportLifetime.swift) is not the same as its current platform view. Detaching the view does not end the reader, and a retiring attachment cannot remove a successor's input handler. Queued input must belong to the same uninterrupted input interval. Geometry may arrive before appearance but must not be accepted from a previous attachment. The [external surface](../../Sources/YamiboXUI/Features/Reader/Shared/ExternalDisplay/ReaderExternalSurface.swift) waits for its mounted viewport to render before handing off or accepting input.

The [scene-local safe-area probe](../../Sources/YamiboXUI/Features/Reader/Shared/Chrome/ReaderShellSupport.swift) uses the window the reader actually lives in; a safe-area-ignoring SwiftUI surface can report zero even in a window with insets. The probe reports after the current layout pass so the state write does not occur inside SwiftUI's render transaction. The [device surface](../../Sources/YamiboXUI/Features/Reader/Shared/ReaderSessionView.swift) retains its usable width, including cutouts, owns Pencil input, and observes its [panels](../../Sources/YamiboXUI/Features/Reader/Shared/ExternalDisplay/ReaderPresentationSupport.swift) in a device-side view body. Remote text menus display controls on the device while the [current viewport](../../Sources/YamiboXUI/Features/Reader/Shared/ExternalDisplay/ReaderDeviceTextMenu.swift) still owns selection and acts on it.

For external vertical reading, the [scroll relay](../../Sources/YamiboXUI/Features/Reader/Shared/ExternalDisplay/ReaderExternalScrollRelay.swift) borrows the device scroll view's native touch physics but reads current range and position from the external target. It synchronizes before handling a new touch, preserves touch-down motion while anchoring at the target's live position, and rebases the next delta when a relayout moves the target. The device's bounce cancellation does not clamp the external offset, so the relay performs that clamp on any still-attached target, including a covered one. The menu is a frame-pinned descendant of the scroll view so a pan can cancel its tap. An extra finger explicitly interrupts the gesture and pending edge actions; limiting the pan to one touch alone does not stop an already-tracked first finger.

See [the reading architecture](../architecture/readers.md#会话注解与外部能力) for the full session flow and [ADR 0013](0013-external-display-lifecycle.md) for external scene ownership and privacy.
