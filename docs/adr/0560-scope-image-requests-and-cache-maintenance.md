# 区分图片请求身份、缓存身份与重试状态

普通图片字节仍按 URL 缓存，但同一 URL 的实际请求可能使用不同的 Cookie、Referer、User-Agent 或加载代次。[图片数据管线](../../Sources/YamiboXCore/Infrastructure/Images/YamiboImageDataPipeline.swift)关闭 Nuke 的请求合并，由[加载协调器](../../Sources/YamiboXCore/Infrastructure/Images/YamiboImageLoadCoordinator.swift)按完整上下文合并；协调器也是封面失败计数的唯一所有者，避免同一请求或其重放因多个消费者被重复计数。请求标识使用长度前缀避免不同字段拼接碰撞，不抹除决定资源的 URL 查询参数。持久化冷却身份不含原始凭据、内存代次或临时通行状态，因此冷启动保留还有效的冷却状态。

## 传输与恢复

Nuke 接收 delegate 的分块数据而非一次性聚合结果，以便保留未完成图片的局部字节用于续传。任务持有其 delegate，delegate 的响应状态仅在串行回调中访问。已记录的重定向错误优先于随后可能到达的响应回调；仅完整、限量的合格防护文档可交给验证器，普通成功响应有界检查后仍流向 Nuke。没有执行器 attempt 的缓存查询只能读取，不得隐式发起网络请求。[论坛请求与图片传输边界](../architecture/networking-and-routing.md#图片下载与网页边界)记录了通用准入策略。

恢复通知传输完整 revision 快照而不是单条增量，避免通知合并时丢掉另一张图的恢复。更新通行状态只给仍可恢复的失败请求发信号，不清缓存、不更改成功图的身份；迟到信号不能新建操作。登记失败时主动检查最新会话，以覆盖通行状态先更新、失败后登记的竞态。网络单次共享和有效性检查分别防止同一操作重复启动、以及账号/封面变化期间迟到的结果重新发布。

## 离线字节与维护

[图片加载管线](../../Sources/YamiboXCore/Infrastructure/Images/YamiboImagePipeline.swift)允许把普通缓存中的有效阅读字节提升为持久化封面，但封面网络请求不写该缓存；阅读者若加入封面的无缓存请求，可为正文另外写入普通缓存。无效封面字节可能也在普通缓存中，重试前淘汰该副本。成功解码而非成功 HTTP 响应解除冷却；同 URL 的阅读器成功可以淘汰更早的封面失败结果，但不取消其他阅读消费者。显式账号操作即使重新取得相同认证 Cookie 也清理该状态，普通图片缓存清理或被动通行状态更新不这样做。

[缓存维护器](../../Sources/YamiboXCore/Infrastructure/Images/YamiboMaintainedImageDataCache.swift)保留 Nuke 的暂存和文件写入，但接管启动检查和淘汰：仅命中缓存的会话也应接受维护。先在 Nuke 队列之外同步冲刷暂存，以免重入队列或把刚删除的旧字节计入统计；淘汰则在 Nuke 写队列中执行，避免文件在检查与删除之间被替换。是否仍属当前维护与文件删除受同一把锁保护，否则刚提交的清空操作仍可能与旧淘汰交错；进行中的维护保留其调度位，只有观察到新写入才排下一轮。缺少完整清单时跳过淘汰，删除后按实际分配字节重新统计。

现行容量、封面来源回退规则和文件所有权见[下载、缓存与封面存储](../architecture/downloads-and-storage.md#5-图片管线与授权上下文)。
