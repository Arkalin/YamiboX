# 将启动、窗口续读和应用级同步分开

本地启动状态独立于 WebDAV 和阅读器恢复：应用先交付可用的本地壳，窗口各自捕获路由、账号代次和进度基线，再等待应用持有的同步轮次。关闭窗口不取消别的窗口也在等待的同步。同步可能已落下本地合并却在上传时失败；恢复因此比较窗口自己的前后进度，而不只看整个轮次的结果。

- **恢复只使用仍然有效的路由。** 显式导航消耗窗口的一次启动恢复机会，不覆盖用户新选的路由；Store 等待后要重新检查代次。旧漫画身份不明确时保留旧路由，不按标题猜测。[智能漫画](0711-store-explicit-board-reader-selection.md)关闭时用精确的单帖进度键；通用线程查询还能按「当前章节」命中目录级进度，可能把续读带到另一帖。单帖收藏也按该帖 ID 查找，不再借用目录名。详见 [AppContinuityWorkflow](../../Sources/YamiboXCore/App/AppContinuityWorkflow.swift)。
- **阅读器生命周期入口同步写入。** 同一调用方依次上报的呈现、位置变化、关闭不能由独立任务重新排序；锁使这些无等待入口按调用顺序变更状态。运行时在返回前同步注册 Store 变更流，避免订阅依赖任务调度时机；运行时停止只取消它持有的观察，不撤销已交给续读流程的任务。前后台转换返回是否实际接收了新阶段，平台层据此去重系统副作用。详见 [AppRuntimeCoordinator](../../Sources/YamiboXCore/App/AppRuntimeCoordinator.swift)。
- **同步在失败和生命周期切换时保留待处理意图。** Store 通知与同步参与者由同一注册表产生，不能只接入其中一侧。安静窗口被取消或同步在途时保留变更；失败时把候选交回下一次变更信号或全量检查，不因重新入队自启重试。进入后台时即使防抖尚未运行，也在同一轮次完成全量标记和同步，失败则保留全量检查需求。前台同步绕过本地编辑间隔，但服务仍可合并短时间内的无变更检查；自动同步错误不阻塞应用。后台保护只是系统授予的短时租约，到期取消运行内容，不负责调度或延长执行。参见 [WebDAV 同步](../architecture/webdav-sync.md)。
