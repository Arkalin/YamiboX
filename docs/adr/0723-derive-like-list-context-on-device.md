# 喜欢列表的排序和摘录上下文在本机派生

书内顺序与摘录周围的文字取决于设备实际取得并排版的章节，不作为可编辑内容上传。章节序号未解析时，小说可用帖子页、段序号与偏移排序，但同一论坛页的多章可能需要在下次阅读时重排；漫画锚点只有章节和页内序号，不能把页内序号视为全书位置。排序键从当前锚点重算，不接受调用方遗留的键。已有的序号和前后文在排版后补齐，不更新条目的编辑时间；否则每次打开阅读器都会让同步误以为发生编辑。仅在变化时通知观察者，以免无变化的补齐触发自身重复执行。

列表在高亮前保留足够读懂短语的分句开头，并限制前缀长度，避免高亮被挤到行外；后缀用于填满余下的一行，可以延伸到句末并保留句末标点，但不跨换行。捕获和旧条目补齐共用同一套边界规则，调用方在持有排版正文时截取上下文。合并锚点时，前后文必须来自构成合并范围两端的条目，不能取落在合并范围中间的截段。周围正文不在喜欢数据库中，因此数据库迁移不能补齐它。
