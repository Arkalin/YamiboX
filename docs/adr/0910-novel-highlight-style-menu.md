# Use a dedicated edit-menu root for novel highlight styles

[NovelLikeStyleMenu](../../Sources/YamiboXUI/Features/Reader/Novel/TextKit/NovelLikeStyleMenu.swift) presents the five colors and underline as a separate horizontal `UIEditMenuInteraction` root, for both capture and restyling. On the reader path, a nested menu opens a vertical page, and a button-hosted small menu wraps instead of keeping a single strip. The system bar puts the seventh item on another page, so note and remove stay in the parent menu.

The system bar uses the image only when the action has an empty title. Give the swatch image the localized accessibility name and use the base palette against the system menu material, not ink adapted for the reader's page. The slot size is controlled by the system; the swatch size affects only how much of it is filled. Underline uses a distinct glyph and the swatches omit a selection ring to keep the controls visually subordinate to the text.

[NovelTextSelectionController](../../Sources/YamiboXUI/Features/Reader/Novel/TextKit/NovelTextSelectionController.swift) resolves an explicit style before writing the annotation instead of capturing and then recoloring it. Read the last-used style at capture time when the entry point does not show swatches, such as adding a note, so another session's choice takes effect and the user can get to the note editor in one action. Route the note request back through the SwiftUI reader, which owns the sheet slot, instead of presenting it from the UIKit menu.

Prime the haptic generator when an available selection action is offered. [NovelLikeHighlightController](../../Sources/YamiboXUI/Features/Reader/Novel/TextKit/NovelLikeHighlightController.swift) repaints a successful capture alongside its haptic and applies a restyle immediately, rather than waiting for the store's invalidation to round-trip. The subsequent reload reconciles with persisted state; a failed restyle reverts if a newer style has not replaced it.
