# 持久化封面分离于普通图片缓存

[封面存储](../../Sources/YamiboXCore/Library/Data/ContentCoverStore.swift)通过 actor 串行检查引用、代次并执行文件 IO，中间不挂起。清理使原始加载代次失效，即使之后又选择同一个图片 URL 也不能接收过期响应；没有索引引用的临时预览不应产生孤儿文件。[图片存储](../../Sources/YamiboXCore/Library/Data/ContentCoverImageStore.swift)有界解码原始首帧，不仅检查头部或已有的内嵌缩略图，保存原始字节；坏副本不阻挡后续获取有效图片。启动迁移完成的标记在清理后保留，否则后续阅读产生的普通缓存可能被误迁回封面。详细的引用、清理失败、迁移规则见 [下载与封面存储](../architecture/downloads-and-storage.md#7-持久化封面的引用迁移与失败恢复)。

列表按批查询减少数据库和 actor 往返，分块限制单个语句的绑定参数数目；允许部分成功的旧列表在批查询失败时回查单个键。事务性业务读取区分失败和缺省，特别是同步导出不能把读失败变成空快照。变更流只负责唤醒，按修订读取的键日志负责弥补流里的合并或跳过；目录键可能在写事务中规范化，不能用写前的键发出过窄的失效通知。图像失效及保留回调由组合根连接，弱捕获图片管线以避免互相持有。
