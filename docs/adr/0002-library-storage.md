# 收藏文档整体存储，封面和运行记录独立持久化

[收藏库](../../Sources/YamiboXCore/Library/Data/FavoriteLibraryStore.swift)在 GRDB 里存为单行 JSON。论坛同步、WebDAV 和整理器都读取整个文档；旧的多表设计也在每次保存时重写全库，并未获得逐条查询的收益。修改在同一写事务内读取、转换并保存文档，避免两个写入方互相覆盖；转换闭包抛错时回滚，并把原错误返回给调用方。读失败不能当作空收藏。

解码兼容旧文档，但不等同于规范化：缺失的删除记录按空集合读取，缺失的字段时钟继承条目的 `updatedAt`；保存和合并时显式重建，保留墓碑、去除悬空位置和标签引用、恢复稳定顺序。同一条目重新收藏或变更身份时，清除仍存活的目标墓碑，变更前的身份则留下墓碑，避免旧设备重新引入重复条目。删除分类也为各被级联删除的合集记录墓碑；单纯重复添加位置不推进字段时钟，以免掩盖其他设备的实质编辑。详见 [收藏文档](../../Sources/YamiboXCore/Library/Domain/FavoriteLibraryDocument.swift)、[条目修改](../../Sources/YamiboXCore/Library/Domain/FavoriteLibraryDocument+Items.swift)及 [WebDAV 合并规则](../architecture/webdav-sync.md#各数据集的冲突粒度)。

`contentUpdatedAt` 是派生内容日期，不是刷新时间或编辑时钟。旧格式混入过刷新时间和任意页日期，解码只丢弃不可信的日期，允许未来刷新恢复为更早的真实时间；普通回复、小说作者编辑、漫画章节发布时间的范围不同，修改目标类型也清空这个日期。网络读取完成后才写入日期的流程不得复活期间已经删除的收藏。批量删除带身份而非旧对象跨越远端等待，在最新事务内按请求顺序删除并保留首次删除时钟；批量导入和更新索引仅在其所属的文档快照内有效，不能随位置可能变化的重建继续使用。日期解析复用 [DiscuzEditedDateParser](../../Sources/YamiboXCore/Forum/Domain/DiscuzEditedDateParser.swift)，避免收藏和帖子各维护一套编辑时间语法。

封面是内容元数据，清空收藏不清理封面。同步运行记录和收藏更新跟踪也是独立的本机运行状态，不进入会经 WebDAV 同步的设置；更新记录按行保存，目录身份变更可在共享事务中规范化其引用。正常应用使用共享数据库，测试或预览可通过非标准 defaults 走隔离数据库。

[论坛收藏同步日志](../../Sources/YamiboXCore/Library/Data/FavoriteSyncRunStore.swift)与运行元数据分开存储，避免每个条目进度都重写不断增长的日志。旧的整份快照仍可读取，下一次保存才拆分；新条目只有在基线版本和计数都匹配时才追加，基线缺失或被同长度的全量写入替换时则完整写入。更新父行而不是使用会级联删除日志前缀的 `REPLACE`。读取最近运行记录不按状态过滤，由调用方决定是否将上次未完成的运行标记为中断。检查点先持久化再发布，过时或乱序的写入结果不能建立下一次追加的基线；隐藏卡片只改单个展示字段，不能写回过时的运行和日志副本。日志和警告存储语义值，由展示层负责本地化。
