# 收藏与封面各自按写入边界解决 WebDAV 冲突

[收藏合并器](../../Sources/YamiboXCore/Library/Application/FavoriteLibraryWebDAVParticipant.swift)在读取和替换同一份存储文档的事务中合并，避免覆盖同步进行中的本地编辑。位置、标签、展示名和论坛映射各按自己的时钟选较新值，同时间优先本端。使用整条收藏的时钟会让设备之间无关的字段编辑相互覆盖；对位置或标签直接求并集则会让旧设备重新加回已经移除的值。合并写回时保留收藏、类别、合集和标签的删除记录。分类、合集和标签 ID 不复用；检查合集的父分类也能处理从未同步到删除端的并发新合集。收藏 ID 则来自内容，重新收藏可以复用；时间相同允许存活，成功重新收藏废止旧删除记录。

指纹用有界大小的摘要表示本地文档和删除记录，而不是把整个变大的收藏库嵌进同步设置。旧 v2 封装中移除的 `tombstones`、`clocks` 以及早期收藏项的 `coverURL` 不再读取；解码可忽略旧字段，迁移到文档真实的时钟与删除状态不要求提升封装版本。引入 revision 前的封装仍按时间比较；详见 [WebDAV 兼容边界](../architecture/webdav-sync.md)。

[封面参与者](../../Sources/YamiboXCore/Library/Application/ContentCoverWebDAVParticipant.swift)单独同步图片 URL、来源和用户选择，因为只同步收藏无法在接收设备上恢复这些数据库行。封面冲突按行解决，和存储每次更新增加一份行时间戳的粒度一致；强制文字、手动选择和自动选择一起保留。同步不传图片字节。封面和收藏合并器对重复记录键都保留较新的记录，而不假定解码会经过实时写入的归一化路径；老端或经手工编辑的内容不应该因重复键使后续每次同步崩溃。
