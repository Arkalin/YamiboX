# Preserve the reader when presenting companion UI

- [Book opening](../../Sources/YamiboXUI/Features/Reader/Shared/BookOpeningTransition.swift) gives each visible cover its own namespace. The same favorite in a collection and in the library behind it must not compete as the return target. Keep the source fixed across the presentation and let SwiftUI own the zoom, interactive cancellation, offscreen fallback, and Reduce Motion. A quick scroll-view tap may not expose a pressed frame; finish the missing press feedback without requiring a long touch or delaying Reduce Motion navigation.
- [Original post from chapter comments](../../Sources/YamiboXUI/Features/Reader/Shared/Comments/ReaderChapterCommentsViews.swift) opens over the comments sheet so closing it restores that sheet and closing the sheet returns to reading. The full-screen post is marked as discussion context: it is a companion to the active work, not a separate visit to put in browsing history.
- [Failure details](../../Sources/YamiboXUI/Features/Reader/Shared/ReaderLoadStateView.swift) use a native presenter for collection-cell hosts because a SwiftUI sheet's navigation stack cannot be hosted there. Native actions register the same priority and visible bounds as SwiftUI controls so the underlying zoom/gesture surface does not steal input.
- [Image prefetch](../../Sources/YamiboXUI/Features/Reader/Shared/ReaderImagePrefetchCoordinator.swift) is best effort: if it fails, display loads still retry independently. If a cancelled request finishes after the same URL re-enters the window, its completion must not clear the replacement request.
