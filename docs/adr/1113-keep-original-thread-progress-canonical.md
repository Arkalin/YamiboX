# 原帖只持久化正序、未筛选的阅读位置

Discuz 的「只看楼主」和「倒序浏览」会改变分页和楼层顺序。切换时清除原锚点并从第 1 页加载，这两个模式都不写阅读进度或浏览历史，否则再次按默认顺序打开时无法恢复到同一楼层。只有正序未筛选的首页首帖可用于确定楼主；没有加载该页的会话先查首页缓存，再联网，仍无 uid（例如匿名或已删首帖）则不启用该筛选。菜单从模型读回筛选状态，而不是假设切换成功；若切换后的加载取消并保留旧内容，下次进入须先完成待加载的筛选。倒序首页的首个可见楼层也不应承接原帖标题和计数。

自动恢复按设置开启，明确指定的帖子、深页或阅读位置优先。保留的原帖模型在接收新的章节原帖请求时，以新意图替换旧锚点和筛选；回复提交后的定位也是可被更新的翻页或模式切换作废的旧意图。若定位候选页不含回复，刷新提交前所在页，而不是跳到无关楼层。同页刷新继续保留锚点，跨页加载则不复用旧楼层。普通原帖与讨论伴随页的历史边界见[原帖路由决策](0004-forum-routing.md)；同一访问内的翻页只更新已有历史活动，不重建被删除的记录。

滚动使用 SwiftUI 的原生目标定位，等待真实布局，不依赖猜测的固定延时；长帖子定位在楼层开头，恢复不做动画，避免把动画途经的楼层写回进度。用非零但极低的可见比例识别长楼层，因为零有时会命中不可见的缓存行；不过可见 ID 的顺序不一定是页面顺序，也不能用会预取行的 `onAppear` 作为可见性信号。恢复期间屏蔽初始顶部报告，看到目标后先用恢复锚点初始化当前位置，保证未滚动就退出也不丢锚点。退出写入由独立任务执行，不随视图任务取消。
