# Prefer template structure to generic text scanning on Discuz pages

Keep the user-space parsers split by page type, with shared extraction functions available across sibling extensions and repeated selector names private to their file. Reading a whole container as text can blend action controls, metadata and user content. Prefer scoped markup for known touch and desktop shapes; require evidence of the intended page before interpreting no matching rows as a valid empty page.

Examples of the distinguishing shape:

- A friend row can have a profile avatar and a later profile name; destructive or messaging links can carry a user ID but are not identity anchors. The friend request float carries the name in the body, not the dialog title.
- The private-message list (`#pmlist`) stores the partner name in the direct text of `.mtit`; child `.mtime` and `.mnum` are separate. One-to-one conversations are identified by `touid`, not the group-conversation `plid`. Conversation rows in `.msgbox` distinguish `.friend_msg` and `.self_msg`.
- Notifications take their identifier from a row's `notice` attribute and content from `.mbody`, not the filter link and relative timestamp also in the row. The unread probe reads counters from the PM list rather than marking individual conversations or notices as read. A digit-bearing but unrecognized badge should not silently clear the count. Invalidate the active probe before yielding after a read, coalesce completions during a probe into a single follow-up, and check account generation again before accepting a response in case the observer has not seen the account change yet.
- Profile credits put the value inside a `span` and the label outside, so do not assume “label followed by number”. Total credits must be matched before its shorter substring “credits”. Credit history can contain identical transactions with no server row ID; occurrence distinguishes them instead of dropping later rows.
- Thread and blog title markup may share a container with a badge, category or excerpt; strip the wrapper, not words from the actual title. In a blog detail, `.view_tit` supplies the subject and `li.mtit` describes the author. Mobile counts can be positional or icon-associated rather than labeled; search counts belong to the result heading because the searched text can itself contain digits. Parse explicit announcement status separately from an empty list, and do not let an empty/sticky-only board reintroduce pinned threads via a generic anchor scan. Page count inference cannot fall below the current page, even when the last page links only backward; for a tag deep link with no pager, recover once rather than treating the requested number as the total.
