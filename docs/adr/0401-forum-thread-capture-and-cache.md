# Separate captured forum content from the reader's cached projection

Discuz relative labels describe the time of a specific response, not the time the reader opens its cache. Resolve them once against page capture time, or leave them unresolved when no capture time is available. When exact desktop tooltips exist, read them before mobile labels that can omit seconds. In touch markup, count elements next to a relative label are not part of its value; scope to the author metadata and exclude its counter child to avoid changing “3 小时前” into “203 小时前”. The shared edit-note parser works on text so favorites and HTML parsing do not maintain divergent simplified/traditional matchers. One pattern captures both the sentence and its timestamp. Each call reuses one formatter across attempts without sharing mutable format selection across callers.

The post-body projection copies the DOM before stripping footer metadata and adding images that Discuz renders outside the message body; a render that only walked the body lost those images. Add just the image elements, not the surrounding download and size controls, and deduplicate them against body images. The HTML attachment parser still owns the file metadata. Deduplicate matches from overlapping selector families by DOM identity without changing document order. Treat DOM node text as already entity-decoded; re-decoding can corrupt examples that show literal markup. Split text at content structure, not arbitrary length. The block builder accounts for cross-node grapheme joins at the trailing boundary instead of rescanning the accumulated run for each node. The whitespace normalizer supplies a character-boundary map so links, styles and ruby annotations can follow normalized text rather than losing their source alignment.

Cache the forward reader representation only: the cache key includes the author filter but not sort order, so storing reverse pages would swap the content under a forward key. Bump the parser version when changed block semantics require rebuilding. For older entries, reparse stored HTML into a transient ordinary-thread projection, retaining the original payload for novel/offline consumers and keeping the cached blocks when no usable HTML can be reparsed.
