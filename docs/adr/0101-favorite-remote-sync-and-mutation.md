# 收藏同步取并集，只有显式删除操作才删除记录

## 同步与单项操作的边界

在 [收藏同步引擎](../../Sources/YamiboXCore/Library/Application/FavoriteRemoteSync.swift) 中，同步是双向补齐，不是用某一端的列表覆盖另一端。远端存在、但本地还没有映射的帖子会加入选中的分类；已映射的帖子只刷新映射，不改变已选的收藏位置。目标分类中未出现在远端列表的帖子会被推送，包括先前在网页上删掉的帖子。推送后再读取列表可补齐远端 ID 和排序。同步本身不将任何一端的缺项解释为删除。

[单项收藏操作](../../Sources/YamiboXCore/Library/Application/FavoriteCommands.swift) 与同步不同：新增先保存本地收藏，再按用户选择尝试推送，远端失败不撤销本地写入；开启远端删除时，快捷删除先尝试远端操作，失败则不删除本地收藏。[整理器删除](../../Sources/YamiboXCore/Library/Application/FavoriteCommands+Deletion.swift) 容许远端记录缺失或查找解析失败，以便继续本地整理；其他远端错误中止本地批量写入，但之前已完成的远端删除无法回滚。选择删除范围所需的身份跨越网络等待，真正修改的是事务中读到的最新本地文档。

论坛删除需要服务器的 `favid`，本地 UI 的收藏 ID 不能用来替代。网页只给出有效帖子链接或推送未能查出远端 ID 时，允许暂不建立 ID 映射，后续同步再补齐。可依赖的远端响应见[收藏页解析规则](0203-remote-favorite-page-confidence.md)。重新指定位置是本地替换，不是累加或远端操作；新增位置先于移除旧位置，空选择必须交给正常删除流程，以免收藏失去最后一个位置。

## 读取可重试，提交不能覆盖本地快照

引擎重试整次只读探测或分页读取，保留原始诊断来区分单项失败与中止整次运行。不完整响应导致的解析错误可能是暂时的，可有限重试；不保存探测失败的占位收藏。[探测适配器](../../Sources/YamiboXCore/Library/Application/FavoriteRemoteSyncProbe.swift) 自身不做嵌套重试，避免成倍增加请求或丢失原始错误；漫画复用分类或封面所需的首帖页面计算发布时间，不另发请求。封面落库为尽力操作，取消例外。对服务器结果未知的写入不盲目重试，避免重复提交。

同步运行期间可在其他位置整理收藏。引擎在工作副本上应用操作，保存时按身份将排队操作重放到最新文档的事务中，而不是写回过时的数组位置或整个副本。普通操作使用同一闭包处理两份文档；新的远端导入先在副本上校验，再排队重放。取消时仍尝试保存已排队的变更：单独任务负责写入，不继承外层取消，否则 GRDB 的异步访问会终止这次补存。界面拥有同步任务，Core 负责探测、内容和封面元数据、远端写入以及结果记录。

## 以章节帖子为身份，目录只用于投影

收藏目标保持帖子身份和原章节标题，智能漫画模式只改变展示分组和路由。新增时显式的小说类型优先；其他帖子依据版面类型分类，与当时是否启用智能漫画模式无关。已知的历史记录身份可以直接使用，否则缺少版面的漫画帖子可能被分为普通帖。快捷删除按帖子 ID 查找实际保存的目标，因为快捷动作传入的模型没有足够信息重新推导漫画类型。

仅当一个导入的漫画章节会与至少一个**本次导入前已收藏**的同目录章节合并时，才提示它归入已有目录。批量查询候选章节的目录，避免逐条查询；冻结导入前的收藏快照，避免本次新导入的相邻章节互相触发提示。目录可跨版面，需用导入结果及各候选章节的版面分别判断智能漫画模式，不能只看目录中排在最前面的章节。未注入版面设置时使用出厂设置；目录不可读取时可继续导入而不发此提示，但取消要交还给运行级处理。
