# 论坛编辑器与本地草稿

本文说明当前论坛发帖、回复和编辑帖子的 BBCode 编辑路径。日志编辑器使用 HTML 路径，不应套用这里的源码模型或本地论坛草稿契约。标签及参数清单见 [BBCode 兼容性参考](../reference/bbcode-compatibility.md)，块边界的具体回归样例见 [可视投影回归](../tests/forum-composer-projection.md)。

## 职责与数据流

编辑器跨越两个现有模块，没有独立编辑器 target：

| 层次 | 当前职责 |
| --- | --- |
| Core 的 `Forum/Domain` | BBCode 文档、节点、UTF-16 选区、命令、撤销历史、可视投影、列表和表格模型、草稿快照 |
| Core 的 `Forum/Data/Composer` | 文档外部输入适配、HTML 剪贴板转换、服务端编辑能力解析、GRDB 草稿与资源存储 |
| UI 的 `Features/Forum/Composer` | SwiftUI 工具栏和属性面板、TextKit 2 文本视图、会话、图片预览、输入法和系统导入 |
| UI 的 `ForumPageSession` | 表单加载、编辑器连接、草稿恢复、上传及提交状态协调 |

主路径是：服务端 HTML 表单 → `ForumForm` 与 `ForumComposerContext` → BBCode 源码文档 → 可视投影 → TextKit 展示。用户操作生成源码事务，事务再更新投影、表单字段与本地草稿；提交的 `message` 始终来自源码，不从富文本反向序列化。

主要实现入口：[文档模型](../../Sources/YamiboXCore/Forum/Domain/ForumComposerDocument.swift)、[投影](../../Sources/YamiboXCore/Forum/Domain/ForumComposerProjection.swift)、[UIKit 会话](../../Sources/YamiboXUI/Features/Forum/Composer/ForumBBCodeSession.swift)、[页面会话](../../Sources/YamiboXUI/Features/Forum/Pages/ForumPageSession.swift)。

## 源码真值与安全保留

`ForumComposerDocument.source` 是提交、撤销和草稿的唯一正文真值。节点保存源码范围、正文范围、原始开始和结束标记；解析后的属性只用于理解和展示，不能替代原始拼写。

- 切换源码与可视模式只更换投影，不将正文转换成 HTML，也不重新输出整篇 BBCode。
- 未修改部分的大小写、空白、别名、参数拼写及换行保持原样。只改节点正文且参数不变时，沿用该节点原始开始与结束标记；修改参数时允许按客户端语法生成当前节点，不规范化整篇文章。
- 未知标签、无效参数、未配对或交叉嵌套内容作为不透明源码保留，附带诊断；达到 64 层解析深度后保留剩余源码，不自动修复或丢弃。
- `code`、图片地址、附件 ID、媒体地址、帖子密码等字面正文不递归解析内部标签。`groupid` 与 `i=s` 是受保护系统节点，普通节点操作不能修改，源码模式仍可查看原文。
- 可视面板打开时保存节点 ID 和原始节点源码。确认前再次比对；节点已被其他编辑改变时提示冲突，而不是把旧面板内容写到新的节点上。

“无损”针对未修改 BBCode 和局部编辑，不表示任意外部 HTML 都能无损导入。HTML 粘贴会有意去掉可执行及表单元素，将有限的文字样式、列表和表格转换成 BBCode；图片只保留 `alt` 文本，不在导入过程中下载或上传图片。

## 选区、块边界与增量更新

文档和 TextKit 都以 UTF-16 为坐标。`ForumComposerRange` 不应跨过半个代理项；源码编辑会检查范围与边界，多个编辑必须互不重叠，并使用同一修改前源码的坐标。

`ForumComposerProjection` 提供可视文字、spans、来源范围、祖先节点和文本属性：

- 普通文字映射到实际源码；格式标签不占可视文字长度。
- 图片、代码块、表格等复杂节点用对象替换字符承载原生预览，整个预览对应完整节点源码；列表标记也有独立来源映射。
- 块前后需要的可视换行是 `boundary` span，源码范围可以为零。它依赖前文是否为空或已以换行结束，不能当成真实源码换行直接删除。
- 相邻 spans 的同一边界可能有多个合法源码位置，选区通过 upstream/downstream affinity 决定归属；格式化、剪切和插入使用该映射，不按可视 offset 直接切源码。

文档可对无分隔符的普通文本叶子执行局部 splice，并保留稳定节点 ID。投影增量更新的条件更严格：必须是同一文档的下一次单编辑修订、同一可编辑文字叶子、没有条件块边界、没有换行变化，也不能位于段落或正文推导的链接中。任何条件不满足都完整重建。

即使一次输入没有直接编辑复杂节点，前文变化也可能让后继块新增或取消隐式换行。因此含块边界的投影必须重建，且更新结果应与完整重建在文字、spans、属性和来源映射上全部一致。只检查屏幕文字相等不足以证明后续选区格式化正确。

## TextKit、输入法与撤销

`ForumBBCodeTextView` 使用 TextKit 2；平台相关字体、主题、附件视图和尺寸处理留在 UI。正文嵌入式界面与全屏界面共用一个 `ForumBBCodeSession`，会话只接受当前附着视图的回调，已退出的界面不能覆盖新界面的状态。

- 有 `markedTextRange` 时不加载外部源码、不重渲染，也不把中间组合文本提交成普通源码事务。
- 切换模式、打开面板、保存草稿或准备提交前先提交组合输入，再捕获源码选区。渲染期间设置标记，阻止 TextKit 回调形成回路。
- 空选区格式切换首先改变后续输入格式，不立即插入空标签；开始输入时再形成源码编辑。上下标的后续输入状态互斥。
- 段落命令扩展至整段；列表的回车、退格及增减缩进由列表模型产生结构事务，不仅改变屏幕上的项目符号。
- UIKit 自身的 `undoManager` 在此视图中禁用，撤销与重做使用 `ForumComposerHistory`，同时恢复源码和选区。连续输入在选区连续且间隔小于一秒时合组，历史最多保留 200 组；新编辑清空重做，主动移动选区及模式切换会结束输入组。

附件对象按节点 ID、源码和字号缓存，避免普通输入重建所有预览。远程图片通过既有图片 pipeline 与 referer 加载，元数据缺失的附件不猜测下载地址。静态编辑预览不自动播放媒体、执行 Flash 或运行滚动动画，也不模拟论坛访问权限。

## 剪贴板、导入与上传锚点

可视复制同时提供本 App 的 BBCode fragment 和纯文本，跨格式选区保留必要的祖先标签。粘贴优先读取内部 fragment；可视模式可接收经过过滤的 HTML，随后才是图片或纯文本。异步读取期间保留来源锚点，视图或锚点失效后不插入迟到结果。

照片、文件和粘贴图片先做本地读取及图片处理，再显示上传确认。选择素材不等于授权网络上传；取消不发出上传请求。实际上传使用服务端返回的配置，已上传附件仍通过附件 ID 和表单附加字段提交。

上传开始前用 `bookmark()` 保存源码选区。后续源码事务会移动锚点；删除或替换覆盖锚点的内容会使其失效。返回结果还必须匹配账号代次、当前草稿和资源记录：

- 上传成功且锚点仍有效：在原意图位置插入附件 BBCode。
- 上传成功但锚点失效：保留上传结果和附件状态，由用户显式选择插入，不能追加到错误位置。
- 上传失败：保留可用本地资源供重试；未上传完成的附件会阻止正文提交。
- 已上传附件从草稿中移除：只移除本地引用和资源，不调用服务端删除附件接口，也不承诺正文中已有的标签自动消失。

## 草稿持久化与账号隔离

本地草稿只用于 `ForumForm.Kind.thread`。快照包含账号 UID、编辑目标、可恢复字段、源码模式、源码选区、附件引用、服务端初始字段指纹、修订号和更新时间；不序列化 TextKit 属性，也不持久化撤销历史。

字段快照使用白名单，排除只读字段、文件字段、密码类型字段和隐藏令牌。恢复时先取得新表单，以当前字段和合法选项合并快照，不把旧 `formhash` 当成新的提交凭据。BBCode 的 `[password]` 值属于正文，会随源码保存；列表或预览遮蔽不等于本地加密或正文加密。

`ForumComposerDraftCoordinator` 对更新做 500 毫秒防抖，并串行 flush。保存错误会显示为失败状态，不能把内存中的内容称为“已保存”。账号切换前提交组合输入并尝试保存，保存失败会阻止正常切换准备；切换完成后失效当前编辑会话，其他账号不能访问原账号草稿。

GRDB 存储采用三个表保存草稿 generation、草稿 payload 和资源归属。保存要求期待修订号匹配，防止同一草稿的并发覆盖；删除留下 tombstone，拒绝迟到保存复活草稿；清空草稿更换数据库 generation，拒绝清理前启动的保存或导入结果。

本地资源以 UUID 文件放在 `composer-drafts` 目录，用草稿 ID 与账号 UID 记录归属，写入使用原子方式和系统文件保护。导入失败会移除对应文件；删除草稿或清空草稿清理本地资源。未引用资源只在成功 flush 且没有进行中的导入后清理。

退出账号不会自动删除已持久化的草稿；全局清理可以删除草稿和本地资源。上述动作均不删除服务端附件或服务端草稿。

## 恢复、冲突与提交边界

恢复本地草稿先重新加载其编辑目标。编辑现有帖子时，最新服务端初始字段指纹与草稿 baseline 不同会要求用户选择本地版本或服务端版本，不自动合并正文。加载失败可安装一个只含标题、正文的离线编辑表单；离线状态可以继续本地编辑和保存，不能上传、发送或保存服务端草稿，恢复联网后必须重新取得表单。

提交保持服务端 HTML successful-controls 语义：未选中的控件不提交、重复字段名保留重复值、只附带本次点击按钮的覆盖值；BBCode 论坛正文固定 `wysiwyg=0`，编辑器的源码开关不改变这一约定。`bbcodeoff` 和 `smileyoff` 是独立表单选项，不是源码模式开关。

提交先提交组合输入、校验必填项和文件，再给用户确认。确认消费一次固定快照，并检查账号代次；不能因确认弹窗状态被清空而重复发送。页面会话会尝试 flush 本地草稿，但提交路径不以 flush 成功作为唯一网络发送门槛，因此诊断时应分别确认本地保存状态和服务端提交结果。

成功判定不是 HTTP 返回、跳转或非空页面。当前 `ForumPageDocument.submissionAccepted` 要求没有表单、存在已识别的成功提示且没有失败关键词；它是保守的站点响应识别，不是通用幂等协议。

- 明确发布成功后，仅删除与已提交草稿 ID 和 change ID 一致的本地草稿，避免清掉确认后新产生的修改。
- 明确保存服务端草稿后，只标记 `serverDraftSaved` 并保存本地草稿，不将其视为正式发布。
- 权限错误、验证失败、无法识别的 POST 响应、超时或账号切换后的迟到响应不证明成功；保留草稿，不自动重发。再次发送前应检查目标主题或服务端草稿，避免重复内容。

## 维护与验证

改动模型、命令或增量策略时，先核对完整投影契约；改动 UIKit 会话、全屏切换或异步锚点时，还需要真实输入与交互验证。回归至少包含：源码模式往返、未知和损坏标签、块前插入/删除后对末字格式化、emoji 与组合输入、撤销重做、面板取消与冲突、上传确认和迟到结果、离线草稿、账号切换及提交结果不明。

按 [启动参数](../tests/launch-arguments.md) 使用签名的 Local App 与本地论坛验证。当前没有旧的 UI 自动化宿主，不沿用已移除 test plan、历史截图或性能数字作为验收证据。本页的模型说明来自源码核对，不代表本文列出的交互场景已经运行通过。
